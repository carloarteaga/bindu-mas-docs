# Bindu Plugin AI Author Mode (Short Guide)

## Goal

Provide a single, low-ambiguity workflow for humans and AI agents to author Go BPR plugins with minimal errors.

## Official Flow

```bash
bindu-studio plugin init --profile ai-safe
cd <plugin-id>
bindu-studio plugin doctor --source . --pre-release --strict --json
bindu-studio plugin certify --source . --out ./<plugin-id>.tar.gz --json
bindu-studio plugin apply --bundle ./<plugin-id>.tar.gz --target root
```

Certify target rule:
- Use `--target os/arch` (for example `--target linux/amd64`) when needed.
- Repeat `--target` per platform; do not use commas.
- Use `--targets-from-mesh` to include platforms present in mesh.
- For Raspberry Pi 32-bit OS, target `linux/armv7` (legacy `linux/arm` is compatibility alias).

## Edit Zones (Author Contract)

Edit only:
- `main.go` author zones:
  - `OnTrigger`
  - `OnEvent`
- `plugin.json`:
  - `in`
  - `out`
  - `schedules`

Do not edit generated runtime glue or transport layers.

## Hard Rules

- `plugin.json.in` must match `Handshake().Inputs`.
- `plugin.json.out` must match `Handshake().Outputs`.
- If schedules exist, `Handshake().Capabilities` must include `timer:cron`.
- Do not emit message types that are not declared in `plugin.json.out`.

## Anti-Patterns

- Adding hidden side effects not documented in plugin behavior.
- Changing `plugin.json` without updating `Handshake()`.
- Shipping with TODO blocks in critical runtime paths.
- Skipping `plugin doctor --pre-release --strict`.

## Golden Example

Use the scaffold generated by:
- `bindu-studio plugin init --profile ai-safe`

Treat that scaffold as the canonical minimal example for BREP Go plugins.
